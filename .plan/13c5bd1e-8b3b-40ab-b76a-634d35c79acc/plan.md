# 文件类型检测逻辑优化方案

## 背景
当前文件类型检测逻辑过度依赖文件名或sheet名来判断数据类型，导致用户自定义命名时无法正确识别。需要优化为基于固定字段组合的检测逻辑，确保无论用户怎么命名文件都能正确解析导入。

## 各数据类型的固定字段特征（基于示例文件分析）

### 1. 订单数据（CSV）
- **核心字段**：订单号、商品名称、商品数量、商品ID、商家编码-规格维度、商品总价(元)、商家实收金额(元)
- **检测规则**：`订单号` + (`商家实收金额(元)` 或 `商品总价(元)`) + (`商品名称` 或 `商品ID` 或 `商品数量` 或 `商家编码-规格维度`)

### 2. 售后数据（XLSX）
- **核心字段**：售后编号、订单编号、交易金额、售后状态、退款类型、退款金额、申请时间
- **检测规则**：`售后编号` + `订单编号` + `售后状态`

### 3. 运费险数据（XLSX）
- **核心字段**：订单编号、服务费用（元）、收费编号、收费状态、运费补偿状态
- **检测规则**：`订单编号` + (`服务费用（元）` 或 `收费编号`)，且无`订单号`字段（区分于订单数据）

### 4. 商品推广数据（XLSX，多sheet）
- **汇总sheet字段**：日期、成交花费(元)、交易额(元)、总花费(元)、曝光量、点击量等（无商品ID）
- **商品sheet字段**：日期、商品ID、商品名称、成交花费(元)、交易额(元)、曝光量、点击量等
- **检测规则**：
  - 有`商品ID` + `日期` + (`曝光量` 或 `点击量` 或 花费类字段) → 商品推广数据
  - 无`商品ID`但有`成交花费(元)` + `交易额(元)` + `曝光量` + `点击量` → 可能是商品推广汇总数据

### 5. 明星店铺数据（XLSX，多sheet）
- **汇总sheet字段**：日期、花费(元)、交易额(元)、投入产出比、店铺关注量、曝光量、点击量等（无商品ID）
- **品牌词sheet字段**：日期、推广名称、花费(元)、交易额(元)、投入产出比、店铺关注量等
- **创意sheet字段**：日期、创意样式、创意图片、品牌词包、花费(元)、交易额(元)、投入产出比等
- **独特字段**：`投入产出比`、`品牌词`、`店铺关注量`、`创意样式`、`品牌词包`
- **检测规则**：无`商品ID` + (`投入产出比` 或 `品牌词` 或 `店铺关注量` 或 `创意样式` 或 `品牌词包`)

### 6. 直播推广数据（XLSX，多sheet）
- **汇总sheet字段**：日期、总花费(元)、成交花费(元)、交易额(元)、关注量、深度观看、直播评论量等（无商品ID）
- **直播间sheet字段**：日期、推广名称、总花费(元)、成交花费(元)、交易额(元)、关注量、深度观看等
- **独特字段**：`直播间`、`深度观看`、`直播评论量`
- **检测规则**：
  - 有`直播间`字段 → 直播推广数据
  - 有`深度观看` 或 `直播评论量` + 无`商品ID` → 直播推广数据

## 检测优先级策略

采用三层检测策略：
1. **第一层：独特字段检测** - 优先使用各数据类型的独特字段进行判断
2. **第二层：名称辅助判断** - 当字段组合无法完全区分时，用sheet名/文件名中的关键词辅助
3. **第三层：默认归类** - 如果仍然无法区分，默认归类为最可能的类型

## 修改文件清单

### 1. src/pages/UploadPage.tsx
- **修改函数**：`detectFileTypeByContent(fields: string[], sheetName?: string, fileName?: string)`
- **修改内容**：
  - 增加`sheetName`和`fileName`可选参数
  - 重写检测逻辑，按优先级排序：售后数据 → 订单数据 → 运费险数据 → 直播推广数据 → 明星店铺数据 → 商品推广数据
  - 添加辅助函数`hasAny()`、`hasAll()`、`nameContains()`简化检测逻辑
- **调用处更新**：
  - `processXlsxFile`函数中调用`detectFileTypeByContent`时传入sheetName参数
  - `processCsvFile`函数中调用`detectFileTypeByContent`时传入fileName参数

### 2. src/utils/dataImporter.ts
- **修改函数**：`detectFileTypeByContent(fields: string[])`
- **修改内容**：与UploadPage.tsx保持一致的检测逻辑
- **注意**：dataImporter.ts中的函数不需要sheetName/fileName参数，因为它是从assets目录读取固定文件，但为了代码一致性，可以保留相同签名

## 详细检测逻辑（伪代码）

```typescript
function detectFileTypeByContent(fields: string[], sheetName?: string, fileName?: string): string {
  const fieldSet = new Set(fields);
  const hasAny = (...names) => names.some(n => fieldSet.has(n));
  const hasAll = (...names) => names.every(n => fieldSet.has(n));
  const nameContains = (name, ...keywords) => {
    if (!name) return false;
    const lower = name.toLowerCase();
    return keywords.some(kw => lower.includes(kw.toLowerCase()));
  };

  // 1. 售后数据：售后编号 + 订单编号 + 售后状态
  if (hasAll('售后编号', '订单编号', '售后状态')) return '售后数据';

  // 2. 订单数据：订单号 + (商家实收金额 或 商品总价) + 商品相关字段
  if (fieldSet.has('订单号') && hasAny('商家实收金额(元)', '商品总价(元)')) {
    if (hasAny('商品名称', '商品ID', '商品数量', '商家编码-规格维度')) {
      return '订单数据';
    }
    return '订单数据';
  }

  // 3. 运费险数据：订单编号 + (服务费用 或 收费编号)，且无订单号
  if (fieldSet.has('订单编号') && !fieldSet.has('订单号')) {
    if (hasAny('服务费用（元）', '收费编号', '保费', '理赔状态')) {
      return '运费险数据';
    }
  }

  // 4. 直播推广数据：有直播间字段，或有深度观看/直播评论量
  if (fieldSet.has('直播间')) return '直播推广数据';
  if (hasAny('深度观看', '直播评论量') && !fieldSet.has('商品ID')) {
    return '直播推广数据';
  }

  // 5. 明星店铺数据：无商品ID + 有投入产出比/品牌词/店铺关注量/创意样式
  if (!fieldSet.has('商品ID')) {
    if (hasAny('投入产出比', '品牌词', '店铺关注量', '创意样式', '品牌词包')) {
      return '明星店铺数据';
    }
  }

  // 6. 商品推广数据：有商品ID + 日期 + 推广指标
  if (fieldSet.has('商品ID')) {
    if (hasAny('日期') && hasAny('曝光量', '点击量', '总花费(元)', '花费(元)', '成交花费(元)')) {
      return '商品推广数据';
    }
  }
  // 商品推广汇总数据：无商品ID但有成交花费+交易额+曝光量+点击量
  if (hasAny('成交花费(元)', '总花费(元)') && hasAny('交易额(元)', '成交金额(元)') && hasAll('曝光量', '点击量')) {
    // 名称辅助判断
    if (nameContains(sheetName, '商品', '推广') || nameContains(fileName, '商品', '推广')) {
      return '商品推广数据';
    }
    // 默认归类为商品推广
    return '商品推广数据';
  }

  return '未知类型';
}
```

## 验证方案

1. **单元测试**：为每种数据类型准备测试用例，验证检测逻辑正确性
2. **集成测试**：使用assets目录中的示例文件进行测试，确保能正确识别
3. **边界测试**：测试字段缺失、字段变体、名称不包含关键词等边界情况
4. **回归测试**：确保现有功能不受影响，已上传的数据仍能正常显示

## 注意事项

1. **向后兼容**：保留对旧格式的支持，如`保费`、`理赔状态`等字段仍可识别为运费险数据
2. **性能考虑**：检测逻辑应尽量高效，避免过多的字符串操作
3. **错误处理**：当检测为"未知类型"时，应给出明确的提示信息
4. **日志记录**：在开发模式下记录检测过程，便于调试
