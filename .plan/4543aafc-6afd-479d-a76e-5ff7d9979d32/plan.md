# 商品链接分析页面重构实施计划

## 根因分析

### 字段名映射错误（严重）

当前 `ProductLinksPage.tsx` 使用的字段名与实际数据字段**严重不匹配**：

| 当前代码使用的字段 | 实际数据字段（从其他页面确认） | 影响 |
|---|---|---|
| `o['订单金额']` | `o['商家实收金额(元)']` 或 `o['商品总价(元)']` | GMV计算完全错误 |
| `o['商家实收']` / `o['实收']` | `o['商家实收金额(元)']` | 实收计算完全错误 |
| `o['退款金额']` | 需确认实际字段名 | 退款可能为0 |
| `o['折扣金额']` / `o['优惠金额']` | 需确认实际字段名 | 折扣可能为0 |
| `o['商品名称']` / `o['商品']` | `o['商品id']` (注意是小写id) | 商品匹配可能失败 |
| `o['商品ID']` / `o['商品编号']` | `o['商品id']` | 商品ID匹配完全失败 |
| `p['花费']` / `p['推广花费']` / `p['消耗']` | `p['总花费(元)']` / `p['花费(元)']` / `p['成交花费(元)']` | 推广花费可能遗漏 |
| `p['点击']` / `p['点击量']` | `p['点击量']` | 点击量可能为0 |
| `p['曝光']` / `p['展现量']` / `p['展示']` | `p['曝光量']` | 曝光量可能为0 |

**结论**：几乎所有核心指标的字段名都是错的，导致页面数据全部为0或错误值。

### 缺失指标

当前只有7个基础指标，需要增加到15+个：
- 缺失：退款率、客单价、推广点击率(CTR)、推广转化率(CVR)、推广曝光量、折扣占比、推广花费占比、净利润、利润率

### 缺失功能

- 无筛选维度（ROI范围/GMV区间/订单数）
- 无视图切换（卡片/表格/图表）
- 无导出功能
- 无环比对比

## 实施计划

### 文件结构

由于 ProductLinksPage.tsx 需要大幅重构（超过50%修改），拆分为3个文件：

```
src/pages/ProductLinksPage.tsx    — 主页面（录入+筛选+视图切换+导出）
src/components/ProductLinkStats.tsx — 统计计算逻辑（纯计算组件）
src/components/ProductLinkChart.tsx — ROI对比图表（已有，需更新）
```

### Task 1: 创建 ProductLinkStats.tsx — 统计计算逻辑

**文件**: `src/components/ProductLinkStats.tsx`

**核心改动**:
1. 修正所有字段名映射，与 DashboardPage/CostPage/PromotionPage 保持一致
2. 增加完整指标计算

**字段名映射表（修正后）**:

订单数据字段:
- GMV: `o['商家实收金额(元)']` (与DashboardPage一致)
- 商品总价: `o['商品总价(元)']`
- 退款金额: `o['退款金额(元)']` 或 `o['退款(元)']`
- 商家实收: `o['商家实收金额(元)']`
- 折扣/优惠: `o['优惠金额(元)']` 或 `o['折扣金额(元)']`
- 商品名称: `o['商品名称']` 或 `o['商品id']`
- 商品ID: `o['商品id']` (注意小写)
- 订单状态: `o['订单状态']`
- 数量: `o['数量']` 或 `o['购买数量']`

推广数据字段:
- 总花费: `r['总花费(元)']` / `r['花费(元)']` / `r['成交花费(元)']`
- 交易额: `r['交易额(元)']` / `r['成交金额(元)']`
- 曝光量: `r['曝光量']`
- 点击量: `r['点击量']`
- 商品ID: `r['商品ID']`
- 商品名称: `r['商品名称']`

**新增指标计算**:
```
退款率 = 退款金额 / GMV * 100
客单价 = GMV / 订单数
推广点击率(CTR) = 点击量 / 曝光量 * 100
推广转化率(CVR) = 推广订单数 / 点击量 * 100
折扣占比 = 折扣金额 / GMV * 100
推广花费占比 = 推广花费 / GMV * 100
净利润 = 商家实收 - 推广成本 - 折扣成本
利润率 = 净利润 / 商家实收 * 100
ROI = (商家实收 - 总成本) / 总成本 * 100
```

**数据隔离**: 严格使用 `currentDisplayData`，不直接访问 `storeDataMap`

## 数据隔离保证

- 所有数据来源: `useData().currentDisplayData`
- A店 → currentDisplayData 返回 A店数据
- B店 → currentDisplayData 返回 B店数据
- 全部店铺 → currentDisplayData 返回 getAllStoresData()（已去重）
- 不直接访问 storeDataMap
- ProductLink 录入数据(dianfx_product_links) 是全局的，但计算时只从 currentDisplayData 取数据
