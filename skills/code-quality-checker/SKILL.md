# Code Quality Checker - 代码质量检测

## 核心能力

### 1. 代码规范检测
检查代码是否符合团队规范和最佳实践。

**检测内容**：
- 命名规范（变量、函数、类、文件）
- 代码格式化（缩进、空格、换行）
- 注释完整性
- 导入语句组织
- 代码风格一致性

**示例提示词**：
```
检测这段代码的规范问题，并给出修复建议
```

### 2. 安全漏洞扫描
识别代码中的潜在安全风险。

**检测内容**：
- SQL 注入风险
- XSS 跨站脚本攻击
- 敏感信息泄露（硬编码密钥、密码）
- 不安全的依赖版本
- CSRF 漏洞
- 路径遍历漏洞
- 不安全的反序列化

**示例提示词**：
```
扫描这个模块的安全漏洞，重点关注用户输入处理
```

### 3. 性能问题分析
发现可能影响性能的代码模式。

**检测内容**：
- N+1 查询问题
- 内存泄漏风险
- 不必要的重渲染（React）
- 大循环优化机会
- 异步操作阻塞
- 缓存使用建议

**示例提示词**：
```
分析这个接口的性能问题，找出潜在瓶颈
```

### 4. 测试覆盖检查
评估测试的完整性和有效性。

**检测内容**：
- 测试覆盖率分析
- 边界条件测试完整性
- 异常情况测试覆盖
- Mock 数据合理性
- 测试用例质量评估

**示例提示词**：
```
检查这个模块的测试覆盖情况，指出缺失的测试场景
```

### 5. 依赖安全审计
检查项目依赖的安全性。

**检测内容**：
- 已知漏洞依赖检测
- 过时依赖提醒
- 许可证合规检查
- 依赖版本冲突

**示例提示词**：
```
审计项目的依赖安全性，列出需要更新的包
```

### 6. 代码复杂度分析
评估代码的可维护性。

**检测内容**：
- 圈复杂度计算
- 函数长度检查
- 文件大小评估
- 嵌套深度分析
- 代码重复检测

**示例提示词**：
```
分析这个文件的代码复杂度，给出简化建议
```

## 检测流程

### 标准检测流程

```
1. 变更识别 → 识别本次更新的文件和代码范围
2. 分类检测 → 根据文件类型选择检测规则
3. 问题收集 → 收集所有检测到的问题
4. 严重分级 → 按严重程度分类（Critical/High/Medium/Low）
5. 报告生成 → 生成结构化检测报告
6. 修复建议 → 提供具体修复方案
```

### 检测时机

- **代码提交前**：快速检测关键问题
- **Pull Request**：完整质量门禁检测
- **合并前**：安全合规强制检测
- **定期审计**：全量代码健康检查

```markdown
  - 🟡 Medium: 3
  - 🟢 Low: 2

**问题**: N+1 查询问题

...
```

## 质量门禁配置

### 默认门禁规则

| 检测类型 | 阻断级别 | 说明 |
|---------|---------|------|
| 安全漏洞 | Critical | 严重安全漏洞必须修复 |
| 代码规范 | Warning | 规范问题仅警告 |
| 测试覆盖 | High | 核心模块覆盖率需 > 80% |
| 性能问题 | Medium | 性能问题需评估 |
| 依赖安全 | High | 高危依赖必须更新 |

### 自定义配置示例

```yaml
qualityGate:
  security:
    critical: block
    high: block
    medium: warn
  performance:
    high: block
    medium: warn
  coverage:
    minimum: 80
    blockOnFail: true
  complexity:
    maxCyclomatic: 10
    maxLines: 300
```
