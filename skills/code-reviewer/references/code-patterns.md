# 代码模式与最佳实践

## 概览
本文档定义代码审查中使用的标准模式和反模式，用于识别代码质量问题。

## 常见代码异味

### 1. 过长函数
- **定义**: 超过 50 行的函数
- **风险**: 难以理解和测试
- **建议**: 拆分为多个小函数

### 2. 嵌套过深
- **定义**: 超过 3 层嵌套
- **风险**: 可读性差，逻辑复杂
- **建议**: 使用提前返回或提取函数

### 3. 未使用变量
- **定义**: 声明但未引用的变量
- **风险**: 代码冗余，维护困难
- **建议**: 删除或正确使用

## 推荐模式

### 单一职责
每个函数只做一件事，函数名应清晰表达其职责。

### 提前返回
使用卫语句减少嵌套层级：
```javascript
// 推荐
function process(data) {
  if (!data) return null;
  if (!data.valid) return null;
  return transform(data);
}
```

### 命名规范
- 函数: 动词开头 (getUser, calculateTotal)
- 变量: 名词 (userData, totalCount)
- 常量: 全大写 (MAX_SIZE)
